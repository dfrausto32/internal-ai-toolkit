# Benchmarks

Three small, well-defined test applications for objectively measuring output quality across Phase 1 (subagent `.md` files) and Phase 3 (Claude Agent SDK).

The test suites in each `tests/` directory are written by hand — they are the ground truth. They never get generated by Ollama or Claude.

---

## Apps

| App | Description | Primary Skill Tested |
|-----|-------------|---------------------|
| `app_01_rest_api` | FastAPI CRUD service, SQLite backend | Code correctness, API design |
| `app_02_data_pipeline` | CSV ingestion + transformation script | Error handling, edge cases |
| `app_03_cli_tool` | argparse CLI with YAML config | Documentation, argument validation |

See each app's `SPEC.md` for full requirements.

---

## Scoring Rubric

Each run is scored on four dimensions, 0–3 each (max 12 points):

**Test Pass Rate (0–3)**
- 0 — Tests don't run (import errors, syntax errors)
- 1 — Some tests pass (<50%)
- 2 — Most tests pass (50–90%)
- 3 — All tests pass (>90%)

**Code Structure (0–3)**
- 0 — Monolithic, no separation of concerns
- 1 — Basic structure, some issues
- 2 — Clean structure, minor issues
- 3 — Well-structured, follows conventions for the framework

**Test Quality (0–3)**
- 0 — Tests are superficial or missing edge cases
- 1 — Happy path covered, limited edge cases
- 2 — Good coverage including some edge cases
- 3 — Comprehensive coverage, edge cases handled

**Documentation (0–3)**
- 0 — No docstrings or comments
- 1 — Some docstrings, inconsistent
- 2 — Most functions documented
- 3 — Full docstrings, inline comments where needed

## Notes

### app_01_rest_api — Phase 1 first pass (2026-06-05)

**Failure mode:** `qwen2.5-coder:14b` imported `from pydantic.v1 import BaseModel` and used `orm_mode = True`. Modern FastAPI (0.100+) rejects `pydantic.v1` models with `PydanticV1NotSupportedError` at startup — tests couldn't even collect.

**Other issues in Ollama output:**
- Used deprecated `sqlalchemy.ext.declarative.declarative_base()` (SQLAlchemy 2.0 warns, still works)
- Routes registered as `/tasks/` with trailing slash instead of `/tasks` (would cause 307 redirects)
- Used `List[...]` from `typing` instead of built-in `list[...]` (minor, Python 3.9+)

**Iteration log:**

| Run | Failure | Fix applied |
|-----|---------|-------------|
| First pass | `pydantic.v1` import — FastAPI rejects at startup | Added Pydantic v2 + no trailing slash to system prompt |
| Retry 1 | `from sqlalchemy.ext.declarative import DeclarativeBase` doesn't exist; `TaskRead` missing fields | Added SQLAlchemy 2.0 import path + subclass pattern to system prompt |
| Retry 2 | **13/13 pass** | — |

**Remaining issues in Ollama output (non-blocking):** `db: SessionLocal` type hint should be `Session`; manual `if not task.title` check instead of `Field(min_length=1, max_length=200)`; no docstrings.

**Claude baseline observation:** Zero review iterations, 100% pass rate, no docstrings. Both models score 0/3 on documentation — neither adds docstrings unprompted. The 1-point structure gap (3 vs 2) reflects Claude defaulting to correct Pydantic/SQLAlchemy idioms without instruction.
